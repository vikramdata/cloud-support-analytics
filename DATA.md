# Data

All data is synthetic. It is generated by `generate_data.py` (seed 42) because no public dataset contains real enterprise support tickets. The generator simulates Google Cloud–style support operations from Jan 2025 to Sep 2026.

| File | Rows | Grain |
|---|---|---|
| `support_cases.csv` | ~57K | one row per support case |
| `csat_responses.csv` | ~17K | one row per satisfaction survey |
| `customers.csv` | 1,800 | one row per customer (with support tier) |
| `agents.csv` | 140 | one row per support agent |
| `products.csv` | 9 | one row per Cloud product |
| `sla_targets.csv` | 12 | first-response target per support tier × priority |

## Simulated patterns

- Case volume grows ~35% over the period, is higher on weekdays, and dips in summer and December.
- Seven incident days each add a P1/P2 surge on one product, which pushes response times past target.
- First-response time depends on support tier and priority. Resolution time depends on priority and on whether the case was escalated.
- CSAT drops when a case misses its response target, is escalated, is reopened, or takes unusually long to resolve.

## Planted data quality defects

These are intentional, so the dbt tests and the data quality dashboard page have real issues to catch.

| Defect | Approx. rate | Caught by |
|---|---|---|
| Duplicate case rows | 0.4% of cases | dedup in staging + `unique` test |
| `resolved_at` earlier than `created_at` | 0.2% of cases | timestamp-order test, flagged and excluded from durations |
| Missing `assigned_agent_id` | 0.8% of cases | `not_null` test (warn), "Unassigned" bucket |
| CSAT score outside 1–5 | 0.3% of surveys | `accepted_values` test, excluded from CSAT |
| Survey for a case that doesn't exist | 0.2% of surveys | `relationships` test, excluded |
